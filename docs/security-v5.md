# Backend V5: staging dan cutover

**Jangan deploy ke Master produksi sebelum persetujuan admin.** Branch/PR ini tidak menjalankan deployment atau migrasi. Server aplikasi hanya menerima `verifyConnection`, `submitParsedPerjadin` (1 SPD), dan `submitCollectorJson` (maksimal 20 SPD, 750.000 byte per POST). GET memberi kesehatan generik saja. Pengiriman memerlukan akun yang masuk daftar petugas input. Pengiriman tidak menyetujui SPD atau mengubah status transaksi di Satu Kemenkeu.

## Persiapan admin

1. Siapkan spreadsheet **uji** dengan struktur yang sama dan data sintetis saja. Pertahankan seluruh tab/kolom yang ada. Pastikan tab `EPERJADIN_V4`, `EPERJADIN_KOMPONEN`, `EPERJADIN_RUTE`, dan `EPERJADIN_PRESENSI` memiliki header yang dirujuk oleh `INTAKE_SHEETS` di kode V5. Tambahkan **satu** tab privat `EPERJADIN_AUDIT` dengan header: `Waktu UTC`, `Sub Google`, `Operasi`, `Request ID`, `Baris`, `Hasil`, `Alasan`. Tidak ada pembuatan tab, penggantian header, atau migrasi data pada request.
2. Jalankan `npm ci`, `npm test` dan `npm run build:apps-script`. Pada proyek Apps Script **baru** (V8), tambahkan `Code_ePerjadin_V5_secure.gs` dan artefak `apps-script-build/EperjadinRsa.gs`. Tambahkan Advanced Google Sheets Service (`Sheets`, v4). Apabila proyek Google Cloud dikelola sendiri, aktifkan juga Sheets API di sana. Jangan salin fungsi dari V4 atau tambahkan deployment pada proyek lama.
3. Buat Google OAuth Client ID jenis Web application, dengan *authorized JavaScript origins* yang tepat. Gunakan origin staging atau `http://127.0.0.1:4177` untuk pengujian lokal; origin produksi nantinya `https://webbcpapin.github.io` (tanpa path). Pakai client ID terpisah untuk produksi, batasi pengguna, dan tinjau akses proyek serta akun pemilik deployment.
4. Di Script Properties, atur `EPERJADIN_SPREADSHEET_ID`, `EPERJADIN_OAUTH_CLIENT_ID`, dan `EPERJADIN_ALLOWED_EMAILS` (email petugas input, terpisah koma). Untuk membatasi ke domain Workspace, isi juga `EPERJADIN_WORKSPACE_DOMAIN`; backend memeriksa claim `hd`, bukan sekadar akhiran email. Jangan menaruh konfigurasi aktif atau riwayat pegawai di repo. Akses spreadsheet/audit tidak diberikan otomatis kepada petugas input.
5. Buat Web App **uji** dengan pemilik proyek sebagai pelaksana. Jika kebijakan Workspace mengizinkan, gunakan akses transport Web App `Anyone` agar POST dari Pages mencapai kode. Ini bukan akses baca/tulis: server memverifikasi tanda tangan RS256 dan memeriksa issuer, audience, expiry, email terverifikasi, dan allowlist. Jika kebijakan organisasi tidak mengizinkan pengaturan ini, hentikan setup dan koordinasikan alternatif dengan admin. Jangan membuat fallback PIN.

## Uji penerimaan staging

- Buka build biasa dan ukur network/storage anonim. Tidak ada data Master yang diunduh. Uji GET dan POST langsung tanpa token, akun tidak terdaftar, lalu akun uji berizin. Hanya akun berizin dapat menyimpan. Jangan menaruh token di URL, riwayat shell, atau screenshot.
- Kirim SPD sintetis lewat kedua alur. Cocokkan summary, komponen, rute, presensi, dan audit dengan hasil penerimaan. Uji respons hilang dengan mengirim ulang konten identik; hasil berikutnya harus `DUPLICATE`, tanpa baris data baru. Uji total berbeda, tanggal/waktu tidak mungkin, serta SPD yang sudah ada dengan data berbeda; konflik tidak boleh menimpa.
- Uji jalur CORS dan redirect ContentService dari **origin yang tepat**, Google Sign-In/FedCM pada browser petugas, penulisan atomik Advanced Sheets, kuota, dan header/rumus laporan pada spreadsheet uji. Tes repo tidak memakai deployment Google nyata dan tidak menggantikan langkah ini.
- Presensi kosong dan tidak terbaca dibedakan. Tanggal di luar rute atau alamat tidak terbaca ditandai. Status **Perlu Verifikasi Lokasi dan Waktu** bukan pengesahan geotag; pemeriksaan rute/lokasi dan aturan jam lengkap tetap perlu alur peninjauan. Nominal berasal dari sumber, tanpa SBM estimasi atau penetapan tarif dari chat.

## Cutover dan rollback

Setelah staging lolos dan admin menyetujui: cadangkan Master dan inventaris semua deployment yang menunjuk ke sana. Buat tab audit melalui admin, periksa akses berbagi (termasuk **Publish to web**), sediakan deployment V5 terpisah, lalu koordinasikan perpindahan frontend dan pencabutan deployment V4/lama yang bisa membaca Master tanpa autentikasi. Hentikan penulis lama sebelum menerima trafik baru; lock V5 hanya mengoordinasikan request dalam satu proyek Apps Script. Rotasi PIN/token lama dan bersihkan sisa penyimpanan situs dari versi sebelumnya pada browser petugas. Penghapusan kode dari branch baru **tidak** menghapus riwayat publik Git atau mematikan URL deployment lama.

Jika terjadi masalah, hentikan pengiriman V5 atau cabut akses petugas lewat Script Properties; beri tahu petugas untuk tidak mengirim ulang lewat versi lama. Gunakan hanya build/deployment sebelumnya yang memenuhi pembatasan akses yang sama. Jangan menyalakan kembali endpoint baca publik. Pertahankan baris historis dan audit; rekonsiliasi dilakukan admin di Master. Script Properties dan perubahan deployment dijalankan oleh admin, bukan lewat API publik.

Audit berisi waktu UTC, sub Google, operasi, request UUID, nomor urut, dan kode hasil. Tidak memuat identitas pegawai, nominal, alamat, atau token. Percobaan anonim tidak membuka spreadsheet. Rate limit 10 permintaan per menit per petugas berbasis cache adalah pembatas operasional, bukan pengganti proteksi kuota platform.
